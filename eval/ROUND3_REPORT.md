- 규칙 1: MDB에서 유의하게 낮다 → 기각. 8클래스에서는 MDB −0.056 [−0.119, +0.014]로 차이가 줄어든다.

- 규칙 2: `dettato_stem` vs `stem_egmd` MDB +0.197 [+0.133, +0.265], Slakh +0.066 [+0.011, +0.129] → **통과**.
  ADTOF(CC BY-NC-SA)를 못 쓰는 상업 배포에서 쓸 수 있는 드럼 경로로 기록한다. 단서: 드럼 학습 재료에 MUSDB18-HQ가 있다(데이터셋 이용 조건이 비상업). 가중치 라이선스는 Apache-2.0이지만, 상업 사용 전 법적 검토가 필요하다.
- 오염: 드럼 점수는 전부 drum-kit 모델이 냈다(스템 43곡 전부). 오케스트라 모델로 라우팅된 곡은 MDB 믹스 1곡(MusicDelta_CoolJazz)뿐이며, 이 곡은 참고 시스템에만 해당한다.

엄격 F1(옥타브 포함): mix_dettato 0.460 / **0.730 / 0.676**. 비교하면 현행은 0.362 / 0.266 / 0.444, mix_yourmt3는 0.340 / 0.161 / 0.305다.

- 규칙 3: 스템 입력은 두 실베이스 세트 모두에서 CI 하한이 0 이하다 → 기각.
- **믹스 입력이 이번 라운드의 가장 큰 발견이다.** `mix_dettato`는 mix_yourmt3 대비 실베이스 일렉에서 +0.291 [+0.139, +0.432]다. 업라이트는 +0.088 [−0.071, +0.234]로 유의하지 않고, Slakh 신스에서는 −0.086 [−0.172, −0.026]로 뒤진다.
  옥타브 정확도도 높다: 엄격 F1 업라이트 0.676, 일렉 0.730. 이는 `eval/BASS_MODEL_PLAN.md`가 "지켜야 한다"고 한 현행 0.444보다 높다.
  다만 사전 등록 규칙에서 참고 경로였고, 현재 제품의 베이스 모드는 베이스 단독 오디오 입력이다. 따라서 기본값 판정 근거로 쓰지 않는다.
- 실베이스 세트의 오디오 출처가 dettato 학습 데이터와 겹치는지는 모델 카드로 확인되지 않는다. MIDI는 Slakh test라 깨끗하다.
- `BASS_MODEL_PLAN.md`(자체 믹스 → 베이스 소형 모델)와의 관계: 정확도 목표는 dettato가 이미 넘는다. 남은 차이는 크기와 속도다. dettato는 28M 파라미터(fp32 약 110 MB)이고, CPU에서 1분 곡에 약 3분이 걸린다(동시 3개 실행 조건). 계획의 목표는 수 MB, 1분 곡 6초다.

  기본값 교체에는 실제 녹음 다악기 세트(예: MusicNet, URMP, Bach10 등 오염 점검 후)가 필요하다.

## 권고 (다음 라운드 후보, 실행은 사용자 결정)

1. **General 모드**: 실제 녹음 다악기 세트를 사전 등록하고 gen_dettato vs gen_basicpitch를 다시 잰다. 통과하면 교체를 검토한다. 이 경우 Apache-2.0이라 YourMT3+와 달리 배포 라이선스 문제가 작다. 단 크기·속도(CPU 3x 실시간) 문제가 남는다.
2. **믹스 → 베이스 경로**: "전체 곡 → 베이스" 기능을 새 경로로 사전 등록한다. 자체 소형 모델 계획(BASS_MODEL_PLAN)을 시작하기 전에, dettato 증류 또는 그대로 사용하는 방안과 비교한다.
3. **드럼**: 기본값은 ADTOF 유지. 상업 배포 시나리오가 생기면 dettato drums(드럼만 5.6초/분)가 egmd보다 나은 폴백이다.
4. 속도: MPS 오류(grouper의 float64)를 우회하면 Apple Silicon에서 빨라질 수 있다. 저자 코드 수정이 필요해 이번 라운드에서는 하지 않았다.
